# Content Summary

I selected the JSUnconf lecture with Anjana Vakil, titled "Learning Functional Programming with JavaScript" as part of this reflection. In the talk, she addresses functional programming as a paradigm of coding, purity in functions, avoiding data mutation, and then alternative data structures and libraries to implement this style of coding as a counter to ordinary object-oriented programming styles.

## What I Noticed

This video provided overall background for me rather than contributing a single insight about implementation of this scripting paradigm. I feel like I have often heard about immutability, object oriented vs. functional programming, and other (what she calls) "sexy buzz words" but still was struggling to understand them in context and implementation, so for her to give direct examples of what object oriented code vs. its functional counterpart looked like was helpful. I feel like my primary realization was not about the different styles of programming (I knew that OOP and functional programming were different paradigms), but instead about understanding the value of this approach — especially since it can be used to improve processing (rather than duplicating and preprocessing arrays and objects), avoid side effects by introducing "pure" functions, among other benefits. It also seemed to me to be a more straightforward way to approach JavaScript (given its fussy little bugs), so I'm curioous if employing JavaScript in situations where functional programming would be beneficial and Python where objects are needed could be a valuable stack or "go-to." I might be totally wrong on that notion but maybe something worth discussing.
